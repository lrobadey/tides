00 / Boundary

One additional scheduler. No second effect.

Add

A binary Sync mode, one discrete rhythmic-division parameter, one binary Grid End parameter, host PPQ/BPM plumbing, and a persistent-lane scheduler inside the existing grain engine.

Preserve

Free mode, rolling live history, Tide source distribution, Shape, Spread, Feedback, Mix, output safety, telemetry, and the fixed 64-grain pool.

GRID END = 1 · DEFAULT

Shared ending

Lane i begins at boundary + offset(i) and ends at the next shared global boundary. Its audible lifetime is duration − offset(i).

GRID END = 0

Full tail

Every lane receives the full selected duration, even when delayed. It crosses the next global boundary, re-articulates at the same phase one duration later, and never overlaps itself.

02 / Events

Every automated change has one defined commit point.

EventCommit pointResult
Enable SyncNext canonical boundary of selected divisionStop Free births immediately; at the boundary, safety-fade remaining Free tails and launch the synchronized layout.
Disable SyncNext current Sync boundarySafety-fade Sync lanes, reset the Free scheduler, and resume Free births there. Never run both schedulers as a blended mode.
Division changeNext boundary of the old/current divisionThat boundary becomes the new division’s phase origin. This is the deliberate syncopation seam; do not snap the change to the new division’s canonical host grid.
Division + full tailFirst new onset for each laneThe new schedule is authoritative. A still-running old grain ends at its lane’s new onset; a grain that already ended leaves a short gap. No bridge grain.
Density changeNext global Sync boundaryRecalculate the evenly spaced layout. Added lanes enter at their offsets; removed full-tail lanes may finish naturally but receive no new articulation.
Drift + Grid End onNext global Sync boundaryJump directly to the newly interpolated onset layout. User automation provides any desired gradual migration.
Drift + Grid End offOne-cycle formation latencyEach lane uses one interval of duration + newOffset − oldOffset, then resumes the exact selected duration at its new phase. Automation intended for a given cycle must be placed one cycle earlier.
Grid End changeNext global Sync boundaryBinary parameter only: exactly 0 or 1. Turning it on fades cross-boundary tails there; turning it off gives new articulations their full duration.
Transport stopImmediate scheduling stopNo new grains. Existing grains may complete. On resume, wait for the next canonical boundary of the selected division.
Start / seek / loop wrapHost discontinuityClear active grains and stale rolling history, re-anchor to the selected division’s canonical PPQ grid, and wait for its next boundary. Starting halfway through an eighth waits one sixteenth.
Clock unavailableImmediateDo not schedule Sync grains; report waiting for host clock. Free mode remains usable outside a host.
03 / Build

A narrow five-step vertical slice.

Parameters + host snapshot

Add stable APVTS IDs for sync, syncDivision, and gridEnd. Read BPM, PPQ, play state, and discontinuities in the processor; pass a small plain timing snapshot into DSP. Keep all work bounded and allocation-free.

Persistent Sync lanes

Add a Sync scheduler alongside the existing Free scheduler in GranulatorEngine. Reuse the same fixed 64-grain storage, history reader, Shape, Spread, feedback path, wet normalization, telemetry, and limiter.

Boundary state machine

Implement phase origin, cycle snapshots, division/density/drift/Grid End commits, full-tail re-articulation, mode handoffs, tempo-following envelope phase, and transport resets as explicit states—not ad hoc parameter branches.

Minimal editor seam

Add one binary Sync control, switch the visible Size readout between milliseconds and musical divisions, add the binary Grid End control beside Drift, and expose the waiting/latency information chosen below. Do not redesign the visualizer.

Regression ladder

Run focused scheduler/parameter/state tests, the full CTest suite, Debug and Release builds, sanitizer coverage for dense automation, then VST3/Standalone validation. DAW listening remains a separate subjective check.

04 / Acceptance

Prove timing, population, continuity, and preservation.

Division timing

All nine divisions and dotted ratios land sample-accurately across 1, 17, 64, changing, and non-power-of-two block sizes.

Lane geometry

Density 1 and 64, Drift 0 and 1, exact first/last offsets, even interpolation, stable lane identity, and never more than 64 active grains.

Source ownership

One Tide-selected set per boundary; delayed lanes use their assigned anchors. Sync Drift produces no source-offset or playback-speed delta.

Grid End

On: every lane reaches silence at the shared boundary. Off: every lane lasts one full musical duration, crosses boundaries, and never overlaps itself.

Automation

Division, Density, Drift, and Grid End commit at their specified boundaries; full-tail division changes cut/re-articulate without duplicates; Drift exhibits exactly one cycle of formation latency.

Transport + tempo

Start, stop, resume, seek, loop wrap, tempo ramp, missing BPM/PPQ, and starting halfway through a division all follow the locked host rules.

State + UI

Defaults and round-trip state: Sync 0, division 1/8, Grid End 1. Attachments reflect automation and mode-dependent Size display without changing the Free Size value.

Existing sound

Free-mode renders remain unchanged. Tide range, Shape, Spread, Feedback, Mix, output ceiling, non-finite containment, and telemetry continue to pass their existing contracts.

05 / Before code

Four decisions remain. Only one changes DSP.

01 · DSPWhat does Shape do when Grid End shortens a delayed grain?
Choose between compressing the complete Shape envelope into duration − offset, or running the normal full-duration envelope and truncating/fading it at the boundary.

Recommendation: compress the complete envelope so every lane reaches its designed zero cleanly and Shape remains meaningful.

02 · COPYIs “Grid End” the final user-facing name?
The behavior is locked; only the concise label remains. Alternatives include Grid End, End at Grid, or Cut at Grid.

Recommendation: “Grid End” is shortest and already established in this plan.

03 · UIWhat remains visible while Sync is off?
The Size position must return to milliseconds. Decide whether Grid End is hidden or remains visible but disabled; the saved Sync division itself is necessarily hidden behind the Free Size display.

Recommendation: keep Grid End in place but dim and disable it, avoiding layout movement and showing that it belongs to Sync.

04 · STATUSHow much timing guidance belongs in the compact editor?
Two messages are required in principle: no valid clock, and the one-cycle Drift latency with Grid End off. Decide between a persistent micro-status line or tooltips only.

Recommendation: a single small contextual line—“WAITING FOR HOST CLOCK” when unavailable; “FULL TAIL · DRIFT LANDS NEXT CYCLE” only while relevant.
